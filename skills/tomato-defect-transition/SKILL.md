# 测试缺陷修复完成流转

这是专门处理修复完成后交测的流程。其他状态流转使用通用 tomato-bug-transition；不重复执行两个流程。

## 使用前确认

用户必须明确要求流转，并有准确卡片编号。问题询问或只读查看不授权写入。使用使用者已配置的 `gitee` 账号；检查本地 CLI 帮助，不固定 profile 或租户。

先读取卡片、当前状态、实际卡片类型和可用流转。若已在目标状态，则不再写入。只有当前工作流返回且未禁用的动作才能执行，不能永久假定某动作名称总会通向待测试。

## 必填字段

某些测试缺陷工作流要求以下字段。这是展示名称参考，字段 key、枚举、值类型及必填条件必须由当前工作空间的元数据/动作规则核实。

| 名称 | 内容依据 |
|---|---|
| 根因分析 | 已核实的代码或流程原因，不能默认填代码逻辑错误 |
| RD 引入原因分析 | 引入原因证据，不能仅根据问题症状推断 |
| 原因描述 | 为什么发生，区别于症状和解决方案 |
| 修复版本 | 用户指定或有依据的交付版本及当前版本数据源 |
| 解决方案 | 实际实现的修复，结合代码、commit 和修复记录整理 |

已有有效值保留，用户明确要求修改时例外。状态流转请求允许填写有明确证据的必填字段，但不允许编造事实。先检查卡片评论、用户提供的任务上下文、修复记录及已提交代码。证据不足的字段先询问；不要填虚假的通用原因来绕过校验。

版本名称不等于版本 objectId。根据实际字段类型解析唯一版本 ID 或所需值结构，不创建版本、不复用作者的版本 ID。不能普遍把 `4.45.x` 归一到 `4.45.0-alpha`；只有当前团队明确确认了映射时才使用。工作空间版本列表为空不证明自定义版本字段无可选值，应核查它的真实数据源。

下拉字段写实际 schema 的 value，不能猜 label===value。富文本通常需要结构化 Editor 值；按当前字段要求构造，不将历史 JSON 形状当作通用保证。

## 命令发现与执行

```sh
gitee team item view --help
gitee team transition list --help
gitee team field workspace --help
gitee team version list --help
gitee team item edit --help
gitee team transition execute --help
```

常见命令形态（参数以本地帮助为准）：

```sh
gitee team item view '<card-key>' -o json
gitee team transition list '<card-key>' -o json
gitee team item edit '<card-key>' --values '<JSON>' -o json
gitee team transition execute '<card-key>' --transition '<exact-returned-name>' -o json
```

1. 完整读取卡片及当前工作空间的必要字段元数据，选择有证据的值。
2. 写入前展示本轮要补的非敏感字段；证据充分且用户已授权流转时无需额外重复审批。
3. 填写字段，重新读取，确认每项值已持久化。未核验不能继续流转。
4. 重新查询可用动作，以实际返回名称执行一次。
5. 再次读取卡片，只有持久化状态符合目标才报告成功。

CLI 无法使用时可采用已配置的番茄连接器等价操作。写入结果不确定时先在原通道回读，不切换通道重复执行。身份、权限或字段失败不自动扩大权限。

## 失败处理

字段必填错误可能来自动作专有校验，不能仅依据普通字段 `required=false` 排除。确认操作未发生后，发现缺失字段的真实 key/type/value，补齐并核验后才重试。不要按猜测不断试值。

字段更新和状态流转是分别持久化的操作。字段成功而流转失败时报告已填字段和失败状态；超时或结果不明先回读，不重复写入。读取失败时报告未核验，不称成功。

最终回复卡片编号、原状态、所用动作、回读最终状态，以及任何部分成功或未确定信息。不输出凭证、私人修复记录全文或账号配置。
